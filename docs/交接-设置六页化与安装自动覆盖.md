# 交接手册：设置窗六页化 + 安装自动覆盖旧版

> 给接手这件事的 Agent：读完这一份就能开工，不需要先问基础问题。
> 项目：**inklink**（Windows TSF 中文输入法，Rust DLL + x86 C++ librime 引擎，GPL-3.0）
> 仓库：`C:\dsh\work\inklink` ｜ 远端：`ssh://git@ssh.github.com:443/MeloFang/inklink.git`
> 当前版本：**2.2.16**（`VERSION` 文件是唯一真相源）｜ 单测 162 项 ｜ 引擎自测 77 项
> 本手册包含三件事：**任务 A（设置六页化）**、**任务 B（安装自动覆盖旧版）**、**任务 C（导入后热重载，建议顺带做）**

## 0. 三分钟背景

架构是双进程（见 `docs/adr/0006`）：

```
应用进程（微信/WPS/explorer…）
   └─ inklink_tsf.dll      ← 薄壳：按键状态机、候选窗、浮条、联想条
        └─ \\.\pipe\inklink-engine  ← 命名管道
             └─ rime-server.exe      ← x86，链 librime，管词库/学习/语料/AI
```

配置分两处：

| 位置 | 内容 |
|---|---|
| `HKCU\Software\inklink\Config` | 暗色、列数、行数、撤回窗口、学习开关、联想条、AI 四项、笔记目录 |
| `HKCU\Software\inklink\State` | 中英模式、中文标点、浮条位置 |
| `HKLM\SOFTWARE\inklink` | `EnginePath`（引擎 exe 路径） |

程序装在 `C:\Program Files\inklink`，引擎在 `C:\inklink-engine`。

## 1. 环境与规矩（必读，能省你两小时）

### 1.1 工具链与命令

```powershell
# 每次开新会话第一件事：修 PATH（Program Files 下有 GNU rustc，会盖住 rustup 的 MSVC 版）
$env:PATH = "$env:USERPROFILE\.cargo\bin;$env:PATH"

cd C:\dsh\work\inklink

# 单测（162 项）
cd tsf; cargo test --release; cd ..

# 引擎自测（77 项，不碰管道和 librime）
.\rime-server\rime-server.exe --selftest

# 构建 + 部署到本机（自动 Z+1 升版本；只想重部署用 -NoBump -NoBuild）
powershell -ExecutionPolicy Bypass -File tools\deploy-local.ps1

# 打安装包（dist\inklink-<ver>.zip + setup exe）
powershell -ExecutionPolicy Bypass -File tools\release.ps1

# 打「发给同事」的一体化包（dist\inklink-<ver>-同事包.zip）
powershell -ExecutionPolicy Bypass -File tools\package-colleagues.ps1
```

### 1.2 三条铁律（违反必被回滚）

1. **DLL 只能是薄壳**：不含词库、不起线程、`DllMain` 不做事、`DllCanUnloadNow` 恒 `S_FALSE`。
   切分/召回/排序/AI/磁盘 IO 全部在引擎或后台线程。
2. **同步路径 50ms 封顶**：按键处理里不许读大文件、不许等网络。
3. **默认不联网**：任何网络请求必须由用户显式开启（AI 就是靠这一点默认关闭的）。

### 1.3 四个已经踩过的坑（不要重复）

| 坑 | 症状 | 做法 |
|---|---|---|
| **PS 脚本丢 BOM** | CI（PowerShell 5.1）报解析错误，本机 pwsh 7 却正常 | 所有含中文的 `.ps1` 必须 **UTF-8 with BOM**；`.cmd` 必须**纯 ASCII 无 BOM**。改完跑一次 `powershell.exe -NoProfile -Command "$null=[scriptblock]::Create((Get-Content 'x.ps1' -Raw))"` |
| **GitHub 22 端口被拒** | `ssh: connect to host github.com port 22: Connection refused` | remote 已改 `ssh://git@ssh.github.com:443/...`，直接用 `git push origin main` 即可 |
| **tag 与 VERSION 不一致** | CI 第一步就失败「检查 tag 与 VERSION 是否一致」 | 先 `Set-InklinkVersion X.Y.Z` 并提交，再打 tag 推送 |
| **DSH 会话里跑不了 setup.exe** | 安装器写 `C:\Program Files` 报 `拒绝访问`；`MoveFileEx(DELAY_UNTIL_REBOOT)` 报 `ERROR_PATH_NOT_FOUND` | **本会话的沙箱不允许这个 exe 做特权写**（PowerShell 可以）。所以：① 验证载荷用 `inklink-setup.exe --extract <临时目录>`；② 真正安装验证请**让人类在自己桌面双击**；③ DLL 行为验证走 `deploy-local.ps1` |

### 1.4 验收纪律

- **没跑过就不算做完。** 不许写「应该可以」。
- 能自动验的自动验：单测、`--extract` 解包核对、窗口控件状态用 `GetWindowLong`/`BM_GETCHECK` 读、注册表用 `reg query` 读。
- 不能自动验的（GUI 交互、安装器特权路径），**写清「未验证」并说明需要人类怎么做**。
- GUI 自动化按键在本机极不可靠（焦点会被 WorkBuddy/微信抢走），别花时间硬试——直接请人类手测。

## 2. 任务 A：设置窗六页化（P2b）

### 2.1 现状

`settings/src/main.rs`（约 900 行，单文件 Win32，无第三方 UI 库）：

| 位置 | 内容 |
|---|---|
| `build_ui()` @450 | 一页塞了 10 项，坐标硬编码，窗口 560×548 |
| `read_form()` @97 | 收集控件值 → `Config` |
| `load_config()` @346 | 读注册表 → `Config` |
| `save_config()` @389 | 写注册表 |
| `default_config()` @329 | 出厂默认 |
| `on_import()` @647 / `import_all()` @666 | 笔记目录导入 |
| 控件 ID | 101–113（配置项）、1001–1003（保存/恢复默认/关闭） |
| 窗口类名 | `inklink-settings`（`main()` @837 注册） |

现有控件（按 y 坐标）：每页候选列/行(18)、暗色(50)、学习(78)、撤回窗口(112)、联想条(390)、AI 区块(216–360)、笔记目录(418)、状态行(466)、按钮(492)。

**问题**：普通用户打开看到的是一堆技术名词，不知道哪些该动；也没有「改完什么时候生效」的提示。

### 2.2 目标

拆成 6 页，顶部一排页签，底部固定「保存 / 恢复默认 / 关闭」，每项带生效时机标注：

| 页 | 控件 | 生效时机（必须如实标注） |
|---|---|---|
| **1 输入** | 每页候选列数、行数；联想条开关 | 立即（下一次按键/下一次上屏） |
| **2 外观** | 暗色主题 | 立即（下次重绘候选窗、浮条、菜单） |
| **3 学习** | 「从我的输入里学词」开关；撤回窗口（毫秒，0=关） | 立即（下一次选词 / 下一次退格） |
| **4 词库** | 笔记目录输入框、「立即导入」按钮、导入状态 | **导入后需重启引擎**（见任务 C；若完成 C 则改为「立即」） |
| **5 AI** | 启用 AI、提供商、接口地址、模型、API Key | 下一次 AI 请求 |
| **6 关于** | 版本号（`env!("CARGO_PKG_VERSION")`）、许可证 GPL-3.0、诊断工具路径 `C:\Program Files\inklink\diagnose.cmd`、项目主页 | — |

### 2.3 实现建议（照做能少踩坑）

1. **页签用自绘按钮，不要引入 comctl32 的 TabCtrl**。
   理由：本项目全程自绘（浮条、菜单、候选窗），引 SysTabControl32 要 `InitCommonControlsEx` + manifest，反而多一层坑。
   做法：顶部 6 个 `BUTTON`（`BS_AUTORADIOBUTTON` 或普通按钮 + 自己记当前页），ID 用 `2001..2006`。
2. **所有控件一次性创建**，按页分组存进 `Ui` 结构（例如 `vec_input: Vec<HWND>`、`vec_ai: Vec<HWND>`、`vec_about: Vec<HWND>`）。
   切换页时对每组 `ShowWindow(SW_SHOW/SW_HIDE)`。隐藏的控件拿不到焦点，Tab 顺序自然正确。
3. **不要重写数据流**：`read_form` / `save_config` / `load_config` / `default_config` 原样保留，页签只影响可见性。
   这是把风险降到最低的关键——配置读写的逻辑已经稳定，别动。
4. **保持现有语义**（这些是这几天的修复成果，别改回去）：
   - `AI_Enable` 缺失 = 关；关的时候接口/模型/Key/提供商**必须禁用**（见 `apply_ai_enabled()`）
   - `Hint`（联想条）缺失 = 关；只有写 1 才开
   - 「恢复默认」要把所有页的控件都刷成默认值，并同步刷新 AI 可用状态
5. **窗口尺寸**建议 600×520 起，按内容最高的页定。页面切换时不用改窗口大小。
6. **命令行模式不能坏**：`inklink-settings.exe --import <目录>`（`main()` @837 里，不开窗直接导入）必须继续可用，自动化脚本靠它。

### 2.4 验收清单

- [ ] 6 个页签能切换，且**不会同时看到两页的控件**（截图或逐页枚举子窗口核对）
- [ ] 每页的说明文字与实际生效时机一致（尤其「词库」页）
- [ ] 保存后重开设置窗，所有值都还在（6 页全覆盖）
- [ ] 「恢复默认」把 6 页都还原，且 AI 四项回到禁用态
- [ ] AI 未启用时，AI 页那 4 个控件仍然不可编辑（`GetWindowLong & WS_DISABLED` 为真）
- [ ] `inklink-settings.exe --import <目录>` 仍然工作
- [ ] `cd settings; cargo build --release` 零 error；`cd tsf; cargo test --release` 162 项仍全过

## 3. 任务 B：装新版要能自动覆盖旧版（含旧 DLL 被占用）

### 3.1 现状（已有一半）

- `installer/setup/src/main.rs` 的 `cleanup_legacy_install()` @263：
  升级前删卸载登记、删 `Run` 里的旧自启项、删 `C:\Program Files\inklink` 下所有 `inklink_tsf_*.dll`。
  用户**不需要**先跑清理工具（那条路是 2.2.8 及更早版本的补救方案）。
- 卸载登记写成 `inklink-setup.exe --uninstall`（@622 附近），所以应用列表里能正常卸载。
- 文件写入用 `write_file_atomic()`：先写临时文件，再 `MoveFileExW` 原子替换，失败重试 6 次×300ms。

### 3.2 真正的问题

安装包里的 DLL 名字是**固定不带版本**的：`inklink_tsf.dll` / `inklink_tsf32.dll`。

`explorer.exe`、微信、WPS 这些进程会把 `inklink_tsf.dll` 映射到自己地址空间里。
**被映射的文件在 Windows 上谁都不能覆盖**（管理员也不行），于是：

```
write_file_atomic(inklink_tsf.dll) → 重试 6 次全失败 → 报「写文件失败：拒绝访问」→ 安装中断
```

用户看到的正是「装新版装不上 / 装完还是旧版」。这就是这次要解决的核心。

### 3.3 方案（照这个做）

**关键思路：新版本写新文件名，注册表跟着换，旧的自然退休。**

1. 解包时把载荷里的两个 DLL 改名：
   ```
   pf/inklink_tsf.dll    → C:\Program Files\inklink\inklink_tsf_<VER>.dll
   pf/inklink_tsf32.dll  → C:\Program Files\inklink\inklink_tsf32_<VER>.dll
   ```
   `<VER>` 用 `env!("CARGO_PKG_VERSION")`（`tools/version.ps1` 已把 `installer/setup/Cargo.toml` 同步成 inklink 版本）。
   实现位置：`unpack()` @344 里按 `e.name` 改目标名，或解包后 `fs::rename`。
2. **COM 注册指向新文件名**：`dll64` / `dll32`（@556 附近）改成版本化路径，
   64 位写 `HKLM\SOFTWARE\Classes\CLSID\{8F2A…}\InprocServer32`，
   32 位写 `Wow6432Node\...`。`ThreadingModel=Apartment` 不变。
3. **旧文件尽力清**：`cleanup_legacy_install()` 已经在删 `inklink_tsf_*.dll`，但删不掉的要**登记重启后删除**
   （`schedule_delete_tree()` 已有，直接复用；它内部先试 `MoveFileEx(DELAY_UNTIL_REBOOT)`，失败则写 `PendingFileRenameOperations`）。
   注意：**不要删刚写进去的新版本文件**，按名字排除当前 `<VER>`。
4. **卸载**（`uninstall()`）已经整目录删除，无需改动；但确认它同样登记了「重启后删除」。
5. 首次安装（没有旧版）走同一条路，天然通。

### 3.4 为什么这样能成

- 正在运行的进程继续用它们已映射的旧文件，不会崩；
- 新启动的进程按新的 CLSID 路径加载新 DLL；
- 旧文件被占用删不掉 → 登记重启后删除，重启后自动清干净。

`tools/deploy-local.ps1` 早就是这个策略（本机 `C:\Program Files\inklink` 里同时存在 `inklink_tsf_2.2.16.dll` 和若干旧版本名，注册表指最新那个），安装器跟上它即可。

### 3.5 验收（必须真机）

| 场景 | 期望 |
|---|---|
| 微信/explorer 开着，装新版 | 安装**不中断**，走到「引擎实测通过：nihao -> N 个候选」 |
| 装完看注册表 | `InprocServer32` 指向 `inklink_tsf_<新VER>.dll`，文件确实存在 |
| 重启微信后再打字 | 该进程日志 `C:\Users\Public\inklink-tsf-<pid>.log` 首行 `activate … version=<新VER>` |
| 连装两次同一版本 | 幂等，不报错 |
| 应用列表 | 有「inklink 输入法 <VER>」，卸载能删干净 |

> 提醒：安装器本身在 DSH 会话里跑不了（见 1.3 第四节）。用 `--extract` 验证载荷正确性，
> 真机安装请让人类双击，或先在 `deploy-local` 上验证 DLL 行为一致。

## 4. 任务 C：导入语料后让引擎立刻生效（建议顺带做）

### 4.1 现状

`rime-server/rime-server.cc` 里 `load_corpus()` @1251、`load_entities()` @1303 **只在启动时调用一次**（@2540–2541）。
所以设置窗点「立即导入」只写了 `corpus.tsv` / `entities.tsv`，**引擎没重读，必须重启引擎才生效**。

用户对此的直观感受是「导入了但没反应」，和 A 任务里要标注的「何时生效」直接相关。

### 4.2 两个可选方案

- **方案 1（推荐，改动最小）**：`settings` 导入成功后，`taskkill /IM rime-server.exe /F`，
  下次按键 DLL 会自动把引擎拉起来（`ipc::ensure_engine`）。导入是显式操作，杀掉引擎可接受。
  注意：杀之前提示用户「正在打字的话会中断当前候选」。
- **方案 2（更优雅，工作量中等）**：引擎侧每分钟（或每 N 次查询）`stat` 一次 `corpus.tsv` 的 mtime，
  变了就重读。绝不能在每次查询里 `stat`（同步路径 50ms 封顶）。

做完这个，A 任务「词库」页的生效时机就能如实写成「立即」。

### 4.3 验收

- 导入一批新词（比如在笔记里加「微格」），不重启引擎，直接打 `weige` → 首屏出现「微格」
- 引擎日志出现重载记录（方案 2）或进程 PID 变化（方案 1）

