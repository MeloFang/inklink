# 基础词库选型评估（2026-10-21 实测）

> 目的：决定 M0 用哪份中文基础词库。结论在最后。
> 环境：Python 3.13 + jieba 0.42.1 + pypinyin 0.55.0，实机测量。

## 一、三条候选路线

| 路线 | 组成 | 许可 | 词频 | 拼音 |
|:---|:---|:---|:---|:---|
| **A** | Rime `luna_pinyin` 词表 | **LGPL-3** | ✅ 输入法调校过 | ✅ 已切分音节 |
| **B** | A + CC-CEDICT | LGPL-3 + CC BY-SA 4.0 | 部分（CEDICT 无词频） | ✅ |
| **C** | jieba `dict.txt` + pypinyin 词组表 | **MIT** | ✅ 但偏新闻语料 | 🟡 覆盖率低（见下） |

## 二、C 路线实测数据

```
jieba dict.txt 总行数            349,046
其中 2~4 字纯汉字词条            330,349
pypinyin 词组表条目               47,111
被词组表精确覆盖                 43,116  →  13.1%
```

按词频截断后再看覆盖率：

| 词频阈值 | 词条数 | 拼音覆盖 | 覆盖率 |
|:---|:---|:---|:---|
| ≥ 0 | 330,349 | 43,116 | 13.1% |
| ≥ 10 | 94,207 | 21,780 | 23.1% |
| ≥ 50 | 45,481 | 12,929 | 28.4% |
| ≥ 100 | 30,812 | 9,088 | 29.5% |
| ≥ 500 | 9,506 | 3,231 | 34.0% |
| ≥ 1000 | 5,181 | 1,870 | 36.1% |

**读法**：即便只看最高频的 5000 词，也有 64% 没有词组级拼音，只能按单字默认读音拼——多音字（重庆 / 银行 / 长城 / 行业 / 音乐）会大面积注错。**输入法里注错码 = 打不出来**，这不是体验问题，是功能失效。

### 噪声样本（随机抽 20 条 2~4 字）

```
杀人案件 / 唐制复 / 父兼母职 / 代理商 / 入侵 / 资料 / 列克星顿 / 沿岸地区
间接测量 / 余章 / 虞山镇 / 尿路感染 / 于建德 / 决定论 / 砭骨 / 痀偻病
先锋报 / 张金线 / 出如脱兔 / 运筹子里
```

`唐制复`、`张金线`、`运筹子里`、`余章`、`于建德` 属于分词产物的碎片或人名，不是词。词典头部还有大量中英混排条目（`AT&T`、`C++`、`A股`、`B超`），对纯中文输入法是纯噪声，必须过滤。

## 三、许可证的更正（重要）

上一轮我口头说"C 是唯一能保持 MIT 的路线"——**这个说法收回一半**：

- LGPL-3 约束的是「库」。词库作为**独立数据文件**分发、可被用户替换、附带许可证与来源说明时，属于聚合，**不强制主程序采用 LGPL**。
- 因此路线 A 并不堵死 MIT/Apache。C 路线的独有价值（许可干净）大幅下降。

参考：Debian `rime-luna-pinyin` 版权文件标注 `License: LGPL-3`，数据 refined from 新酷音(LGPL)、OpenCC(Apache-2.0)、Android Pinyin IME(Apache-2.0)、萌典(CC0)。

## 四、结论

> **决策（2026-10-21，用户选定）：采用路线 A。** 详见 `docs/adr/0003-基础词库选型.md`。

1. **M0 用 A（luna_pinyin）**：唯一同时具备「词频 + 词级拼音切分 + 输入法调校」的来源，能让 50ms 排序有真实基准。
2. **词库不进 git**：作为独立资源包分发，自带 LICENSE 与来源说明，保持可替换。这样许可决策推迟到发布前，且换库不影响引擎。
3. **C 只作后备**：若发布时对 LGPL 数据包有顾虑，再取 jieba 中词频 ≥ 100 的约 3 万条 + 多音字表合并，清洗成本约 1–2 周。
4. **B 只在需要"专业词覆盖"时才考虑**，且必须接受 CC BY-SA 的传染性。
