# inklink 架构设计 v0.1

> 目标：开源、个性化、越用越准的 Windows 中文输入产品。
> 输入：内置大众词库 → 学习个人习惯 → Obsidian 语料 → AI 优化候选与写作辅助。
> 本文回答四件事：模块怎么切、数据怎么流、Obsidian 怎么用、AI 放在哪。

---

## 0. 三条设计公理

架构里每个选择都能回溯到这三条，冲突时以编号靠前者为准。

| # | 公理 | 推论 |
|:---|:---|:---|
| **A1** | **同步路径 50ms 封顶**：按键到候选刷新必须无感 | AI 永远不在同步路径上；任何 >50ms 的活都异步 + 可取消 |
| **A2** | **代码不进入别人的进程** | 不做 TSF 注入 / DLL / 全局输入钩子接管拼音；崩溃半径 = 自己 |
| **A3** | **个人数据默认不出机器** | 远程 API 是显式动作，逐任务授权，发送前可预览 |

上一版 `rime.dll` 进 explorer → 黑屏，是 A2 的反面教材；`onActivate` 里同步建库 11 秒卡死宿主，是 A1 的反面教材。这两条不是洁癖，是死因。

## 1. 形态决策：为什么不是 TSF 输入法

"输入法"在 Windows 上通常意味着 TSF（`ITfTextInputProcessor`），也就是上次崩掉的那一层。但有一个被忽略的事实：

> **AI 候选天生是异步的**（本地 14B 模型 300ms–3s，API 500ms–5s），
> 而 TSF 的候选更新发生在宿主的同步回调里。
> 把 AI 塞进 IME 的同步路径，就是上次那个 11 秒卡的翻版，只是换了个语言。

所以 AI 输入法在工程上必然是"**同步的轻量候选 + 异步的 AI 补充**"两段式。既然第二段一定要独立进程/独立窗口，那第一段做成面板就是顺理成章，而不是妥协。

| 形态 | 同步候选 | AI 能力 | 崩溃半径 | 落地成本 | 结论 |
|:---|:---|:---|:---|:---|:---|
| TSF 注入 | ✅ 原生 | ❌ 塞不进 | 全系统 | 极高 | **M4 才考虑，且只做薄适配层** |
| 独立面板 | ✅ 需一次热键 | ✅ 天然异步 | 自己 | 低 | **M0 主线** |
| Rime 桥（导出词库/插件） | ✅ | 🟡 Lua 受限 | Rime 进程 | 中 | 作为"M0.5 可选后端" |
| 全局键盘钩子接管 | ✅ | 🟡 | 自己但冲突多 | 中 | 不做，与 A2 冲突且中文场景不可靠 |

**结论**：主线是面板；TSF 和 Rime 都只是 `Adapter`，将来谁接上都行，引擎不动。

```
接入层（可替换）
 ├─ PanelAdapter    ← M0 主线：热键唤起的独立窗口
 ├─ RimeAdapter     ← 可选：把个人词库导出成 Rime 词表，给装了小狼毫的人
 └─ TsfAdapter      ← 远期：薄壳，只转发，不含业务
```

## 2. 分层架构

```
┌──────────────────────────────────────────────────────────┐
│ 接入层 Adapters                                           │
│   PanelAdapter（默认） · RimeAdapter（可选） · TsfAdapter（远期）│
├──────────────────────────────────────────────────────────┤
│ 会话层 Session                                            │
│   上下文捕获 · 候选窗状态机 · 上屏执行 · 撤销              │
├──────────────────────────────────────────────────────────┤
│ 引擎层 Engine            —— 同步，50ms 预算                │
│   拼音解析 → 候选召回 → 特征打分 → 排序 → 分页             │
├──────────────────────────────────────────────────────────┤
│ 学习层 Learner           —— 异步，批量                     │
│   选择日志 · 计数与衰减 · 新词发现 · 词库合并              │
├──────────────────────────────────────────────────────────┤
│ 语料层 Corpus            —— 异步，空闲触发                 │
│   会话缓冲 · 脱敏 · Obsidian 写入 · 全文/向量索引          │
├──────────────────────────────────────────────────────────┤
│ AI 层 Providers          —— 异步，可取消                   │
│   任务路由 · 本地(Ollama) / 远程(OpenAI 兼容) · 缓存 · 降级 │
├──────────────────────────────────────────────────────────┤
│ 存储层 Store                                              │
│   SQLite（索引/统计/日志） + Obsidian（人可读语料）         │
└──────────────────────────────────────────────────────────┘
```

### 2.1 模块职责

| 模块 | 职责 | 输入 | 输出 | 延迟预算 | 失败时 |
|:---|:---|:---|:---|:---|:---|
| **PanelAdapter** | 热键注册、窗口显隐、焦点归还 | 热键、拼音串 | UI 事件 | 唤起 <150ms | 退化为不响应，不影响系统 |
| **Session** | 维护"这一句话"的状态：上下文、已选词、光标位置 | 按键、UI 事件 | 输入上下文 | <5ms | 丢弃本次会话 |
| **Engine** | 拼音切分、模糊音、召回、加权排序、去重 | 拼音串 + 上下文 | 候选列表 | **<50ms** | 回退到纯前缀匹配 |
| **Learner** | 记录选择、更新词频/时间衰减、挖掘新词 | 选择事件 | 计数增量、新词条 | 后台 | 丢弃本批，下次重算 |
| **Corpus** | 会话聚合、脱敏、写 Obsidian、建索引 | 会话文本 | Markdown 文件、索引行 | 后台 | 暂存本地队列，重试 |
| **Providers** | 任务路由、模型调用、超时/取消、缓存 | 任务 + 上下文 | 文本流/结果 | 见 §5 | 静默降级，不打断输入 |
| **Store** | SQLite 读写、词库加载、迁移 | — | — | 冷启动 <200ms | 只读模式 |

### 2.2 进程模型

```
inklink.exe (托盘常驻, ~60MB)
├─ main        UI 线程：窗口、热键消息循环
├─ engine      常驻线程：词库常驻内存（~10万条 ≈ 30MB）
├─ learner     定时线程：每 30s / 退出时 flush 计数
├─ corpus      低优先级线程：空闲 5s 后写入
└─ ai worker   子进程（ollama serve 已在跑）或 HTTP 客户端
```

**为什么 engine 常驻内存**：10 万条词 + 拼音索引约 30MB，换来每次按键 <1ms 的召回。冷启动一次性加载，之后不碰磁盘。

## 3. 四条数据流

### 流 A：打字 → 候选（同步，热路径）

```
热键 ─→ Session 打开 ─→ 用户输入拼音
                            │
              Engine.decode(pinyin, context)
                 ├─ 拼音切分（最大匹配 + 模糊音规则）
                 ├─ 召回：base 词库前缀 + user 词库 + 近期选择
                 ├─ 特征：词频、个人权重、使用衰减、上下文语言模型分
                 └─ 排序 → Top N
                            │
                       Panel 渲染 (≤16ms)
                            │
                     回车 → Session.commit()
```

**预算**：热键 150ms（含窗口创建，可预创建隐藏窗口降到 30ms）→ 首屏候选 50ms → 上屏 30ms。

### 流 B：选择 → 学习（异步）

```
commit(词, 位置, 上下文)
   → events 表 append（WAL，不阻塞 UI）
   → 累计到内存计数
   → 每 30s / 退出：批量 UPDATE term_stats（count+1, last_used=now）
   → 排序时实时生效（内存中的计数就是权威）
```

**关键**：计数先写内存、后落盘。落盘失败最多丢 30 秒数据，不影响打字。

### 流 C：输入 → 语料 → Obsidian（异步，空闲触发）

```
Session 文本缓冲（只保留最近 30 分钟）
   → 空闲 5s / 应用切换 / 段落结束
   → 脱敏（应用白名单 + 敏感词 + 密码框检测）
   → 追加到 <vault>/inklink/YYYY-MM-DD.md 的会话块
   → 每 100 条或每日：语料索引任务
        ├─ 抽取候选词（复用 v1 管线）
        ├─ 写入 terms（source=corpus, weight 低）
        └─ 可选：bge-m3 向量化 → 供 AI 检索
```

### 流 D：AI 补充（异步，可取消）

```
用户停顿 300ms 或按 Tab
   → Providers.route(task) 选取 local/remote
   → 组装上下文：最近 N 字 + 检索片段(top-k) + 风格画像
   → 流式返回，逐字上屏到"预测气泡"
   → 用户按 Tab 接受 / 继续打字则取消
```

**取消语义必须做对**：用户一开始打字，立刻 abort 在途请求，否则会出现"AI 结果盖住新输入"。

## 4. Obsidian 协同

### 4.1 为什么用它，代价是什么

| 收益 | 代价 |
|:---|:---|
| 人可读、可编辑、可被其他工具复用 | 每写一次都是磁盘 IO，不能逐字写 |
| 用户已有知识体系，语料天然带结构（标签/双链） | 格式会漂移，需要 schema 版本号 |
| 天然可备份、可同步（用户自己的选择） | 隐私面扩大到云同步盘（必须警告） |
| 抽取管线可直接复用 v1（标题/双链/标签/粗体） | 笔记与应用文本混在一起，需要来源标记 |

### 4.2 目录与格式

```
<vault>/inklink/
├─ 2026-10-21.md            # 每日一个文件，会话按块追加
├─ _index/
│   ├─ terms.tsv            # 抽取出的候选词（机器可读）
│   └─ state.json           # 处理到哪、schema 版本
└─ _config.md               # 用户可编辑：记录开关、排除应用、脱敏词
```

会话块格式（人读友好，机器可解析）：

```markdown
## 14:32 · VSCode · main.rs
<!-- inklink:session id=7f3a app=vscode win=main.rs -->
今天把 RimeEngine 的初始化挪到后台线程，避免卡住 onActivate。
顺便确认了 DllCanUnloadNow 必须返回 S_FALSE。
<!-- /inklink:session -->
```

- frontmatter 只放元数据，正文是原文，**不加工、不改写**。
- 用 HTML 注释做机器标记，Obsidian 预览里不可见。
- `_index/` 前缀下划线，默认不进搜索/图谱。

### 4.3 写入策略（防 IO 抖动）

| 触发 | 动作 |
|:---|:---|
| 空闲 5s | flush 当前会话块 |
| 切换到别的应用 | flush |
| 会话超过 5 分钟 | 切新块 |
| 单文件 > 200KB | 滚动到 `-2.md` |
| 退出 | flush + 关闭索引 |

写入用"追加 + 单次 open/write/close"，不持有文件句柄，避免和 Obsidian 抢锁。

### 4.4 脱敏与边界

- **总开关默认关闭**：首次安装不记录任何东西，用户主动开启才写。开关旁边持续显示**记录文件所在路径**，并提供「打开文件夹」按钮——用户随时知道自己的字被写到了哪、能直接看到、能删。
- **应用白名单**：默认只记编辑器 / 浏览器 / 笔记应用；终端、密码管理器、银行、聊天工具默认关闭。
- **窗口标题黑名单**：含"密码/银行/登录/私钥"等关键词整体跳过。
- **密码框**：UIA 检测 `IsPassword=true` 立即丢弃该段。
- **长度上限**：单块 > 4KB 截断并标记。
- **一键停**：托盘"静默模式"，立刻停写并可选清理今日文件。

### 4.5 反向：语料怎么变成词库

```
Obsidian .md ──(复用 v1: 标题/双链/标签/粗体/n-gram)──→ 候选词
     候选词 ──(基础词库差集：去掉通用词)──→ 个人词条
     个人词条 ──(与使用计数合并)──→ terms 表（source=corpus, 权重较低）
```

**差集是质量关键**：v1 复跑结果显示"背景/目标/里程碑"这类通用词会混进来，说明只靠权重阈值不够——必须减掉基础词库已覆盖的词，个人词库只收"输入法本来打不出来的"。

## 5. AI 协同

### 5.1 按延迟预算分任务，不要一个模型干所有事

| 任务 | 延迟预算 | 用什么 | 触发 | 失败降级 |
|:---|:---|:---|:---|:---|
| 候选重排 | **<80ms** | ❌ 不用 LLM：n-gram LM + 特征线性模型 | 每次按键 | 回退默认排序 |
| 续写补全 | 1–3s | 本地 `qwen3:14b` / API | 停顿 300ms 或 Tab | 无候选，不提示 |
| 翻译 | 2–5s | API 优先（质量） | 显式命令 | 提示失败 |
| 段落优化 / 改写 | 3–10s | API 或本地 | 选中文本 + 命令 | 保留原文 |
| 语料挖词（离线） | 分钟级 | 本地模型 | 每日一次 | 跳过 |

**最重要的一条**：候选排序**不能**用大模型。14B 在 3080 上单次 300ms 起，放同步路径就违反 A1。排序用特征工程（词频、个人权重、上下文二元组、拼音完整度），必要时加一个 10MB 级的小 rerank 模型。

### 5.2 Provider 抽象

```rust
trait AiProvider {
    fn id(&self) -> &str;
    fn capabilities(&self) -> &[Capability];   // 续写/翻译/改写/嵌入
    fn complete(&self, req: &AiRequest) -> Result<impl Stream<Item = Delta>>;
    fn embed(&self, texts: &[&str]) -> Result<Vec<Vec<f32>>>;
}
```

- `LocalOllama`：`127.0.0.1:11434`，模型 qwen3:14b / bge-m3。
- `RemoteOpenAi`：`base_url + api_key + model`，可换任意兼容服务。
- `Router`：按任务类型 + 隐私策略 + 可用性选路；超时 1.5s 无首字则降级。
- 所有请求**可取消**（`AbortHandle`），随输入变化丢弃。

### 5.3 上下文怎么组装（RAG 的个人化）

```
prompt = 角色与风格 + 最近 200 字原文
       + 检索片段（bge-m3 top-3，来自 Obsidian 语料，同主题）
       + 个人偏好（常用词、语气、禁用词）
```

风格画像不是"训练"，而是从语料统计出的**小档案**（句长、常用连接词、术语表），几十行 JSON，每天更新一次。这样避免"为每个用户训模型"的成本。

### 5.4 隐私闸门（A3 的落地）

| 级别 | 行为 | 默认 |
|:---|:---|:---|
| L0 全本地 | 只调 Ollama | ✅ 默认 |
| L1 脱敏后远程 | 本地替换人名/数字/路径 → 远程 | 需逐任务开启，发送前预览 |
| L2 原文远程 | 不脱敏 | 需显式确认，且在 UI 上持续提示 |

## 6. 数据模型（SQLite）

```sql
terms(id, text, pinyin, source, base_freq, personal_w, updated_at)
   -- source: base | corpus | manual
term_stats(term_id, count, last_used, decayed_w)
events(id, ts, term_id, rank, context_hash, app)   -- 保留 90 天
sessions(id, started_at, app, win_title, chars)
corpus_docs(path, mtime, hash, indexed_at)
settings(key, value)                                -- 含隐私级别、热键、词库路径
```

- 词库索引内存常驻：`HashMap<拼音前缀, Vec<term_id>>`，10 万条约 30MB。
- 事件日志按天分区，90 天滚动删除，避免无限增长。

## 7. 性能预算

| 环节 | 预算 | 手段 |
|:---|:---|:---|
| 热键 → 面板可见 | <150ms（预创建窗口 <30ms） | 常驻隐藏窗口，只 Show/Hide |
| 按键 → 候选 | **<50ms** | 内存索引，前缀桶，无锁读 |
| 上屏 | <30ms | 优先 SendInput Unicode，失败回退剪贴板 |
| 学习落盘 | 后台 | 内存计数 + 30s 批量 |
| 语料写入 | 不阻塞 | 空闲触发，单次追加 |
| AI 首字 | 1.5s 内否则放弃 | 流式 + 超时 + 取消 |

## 8. 演进路线（每阶段可独立交付）

| 阶段 | 内容 | 出口条件 | 预估 |
|:---|:---|:---|:---|
| **M0** | 面板 + 内置词库 + 上屏 + 热键 | 能打出"项目代号赤兔"，延迟达标 | 2 周 |
| **M1** | 使用反馈排序 + 衰减 | 用 3 天，常用词稳定在前三 | 1 周 |
| **M2** | Obsidian 语料 + 抽取 → 个人词库 | 笔记里的词进 Top-3；关掉不写 | 2 周 |
| **M3** | AI 续写 + 翻译 + 段落优化 | 续写采纳率 > 20%，失败不打断 | 3 周 |
| **M4** | 可选 TSF/Rime 适配 | 装小狼毫的人也能吃到词库 | 视情况 |

**M4 是唯一有"上次死因"风险的阶段**，所以排最后，且只做薄适配层——真正的召回/排序仍在引擎进程。

## 9. 未决问题（需要你拍板）

1. **形态**：接受"面板 + 一次热键"作为 M0 形态吗？还是必须一开始就像输入法？
2. **语料默认开关**：默认记录，还是默认关闭、用户手动开？（影响隐私叙事）
3. **远程 API**：M3 默认 L0 纯本地，还是要默认开远程？
4. **基础词库来源**：CC-CEDICT（CC BY-SA）/ Rime 词表（GPL 系）——许可证决定项目协议，要先查清。
5. **开源协议**：若用 GPL 词表，项目可能也得 GPL；若想 MIT/Apache，词库得单独处理。

## 10. 与上一版的关系

| 上一版 | 这一版 |
|:---|:---|
| C++ 写 TSF，librime 编进 DLL | Rust 面板，不碰宿主进程 |
| 同步建库 11s 卡死宿主 | 引擎常驻内存，50ms 预算 |
| 无符号、无联调、靠猜 | 本地可跑、可单测、可日志 |
| 词库和输入法绑死 | 词库/引擎/接入三层解耦，换形态不影响内核 |

v1 的 Python 抽取管线保留在 `extractor/`，作为 M2 的语料→词库实现参考。
