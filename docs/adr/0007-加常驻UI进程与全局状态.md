# ADR-0007：加一个常驻 UI 进程，全局状态放注册表

- 状态：已接受（**第 2 条「常驻 UI 进程」已被 [ADR-0008](0008-浮条进宿主进程去掉常驻UI进程.md) 取代**；第 1 条「状态放注册表」与第 3 条「候选窗留在 DLL」仍有效）
- 日期：2026-10-28
- 相关：[ADR-0006 改用 TSF 输入法](0006-改用TSF输入法.md)、`docs/architecture.md`

## 背景

到 1.0.16 为止 inklink 只有两个进程：

```
应用进程 ── inklink_tsf.dll（按键 / 组合串 / 候选窗）
                │ 命名管道
                ▼
          rime-server.exe（librime + 个人词库 + 纠错）
```

这套结构能打字，但缺三样东西，而它们都是**用户每天会碰到的**：

1. **中英状态是每个应用各一份**（`TextServiceInner::english_mode` 字段）。
   在微信里 Shift 切到英文，切到记事本还是中文 —— 用户看不到任何全局指示，
   只会觉得"输入法抽风"。
2. **没有状态指示**：不知道现在是中文还是英文、有没有开中文标点。
3. **没有设置界面**：模糊音要改 YAML、词库要命令行删、AI 将来更没法配。

## 决定

### 1. 状态放注册表，不放进程内存

`HKEY_CURRENT_USER\Software\inklink\State`：

| 值 | 类型 | 含义 | 默认 |
|:---|:---|:---|:---|
| `Chinese` | DWORD | 1 = 中文，0 = 英文 | 1 |
| `Punctuation` | DWORD | 1 = 中文标点（全角），0 = 保持半角 | 1 |

DLL 在每次按键判定时直接读（`tsf/src/state.rs`），**不缓存、不起线程**。

**为什么不缓存**：`RegQueryValueExW` 是微秒级调用，一次按键读两次完全吃得消；
缓存会带来"点了浮条按钮，另一个窗口 200ms 后才生效"的诡异感。

**为什么不起线程**：`AGENTS.md` 第二条铁律要求 TSF DLL 是薄壳。
`RegNotifyChangeKeyValue` 需要常驻监听线程，直接违反这一条。

**为什么不放引擎或 UI 进程**：那样任何一次中英判断都要走 IPC，而且
"后台进程没起来 / 崩了" 就会导致状态丢失或输入法不能打字 —— 输入法最怕这个。

### 2. 新增一个常驻 UI 进程 `inklink-ui.exe`

一个 exe，两种窗口：

- **浮条**：Win32 自绘（`WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE | WS_EX_TOPMOST`），
  只显示中/英与标点状态，可点击切换。必须轻 —— 它常驻。
- **设置台**：Tauri 2 + 网页界面，**按需创建**（点浮条上的按钮或托盘图标才起窗口）。
  词库管理、模糊音、AI 配置、AI 对话都放这里。可以重 —— 它不常在。

它只读写注册表 + 引擎的词库命令，**不参与按键路径**。挂了不影响打字。

### 3. 候选窗仍然留在 DLL 里自绘

不改成"由常驻进程画候选窗"（Rime/Weasel 的路线）。原因：
现有候选窗已经调好了贴光标、翻屏、鼠标点选、只占 1–3ms；
换成跨进程绘制等于每次显示候选多一次 IPC + 一次窗口激活同步，
是拿已经验证过的东西去换一个没验证过的东西。

## 依据：本机其他输入法怎么分工（2026-10-28 实测）

| 进程 | 归属 | 作用 |
|:---|:---|:---|
| 应用进程内 DLL | 所有输入法（TSF 强制） | 按键、组合串、候选窗 |
| `SogouImeBroker.exe` | 搜狗 | 跨进程服务、词库、全局状态 |
| `SGTool.exe` | 搜狗 | **常驻浮条 + 托盘 + 设置入口** |
| `SogouCloud.exe` | 搜狗 | 云端功能（独立进程，挂了不影响打字） |
| `ChsIME.exe` | 微软拼音 | 输入法宿主进程 |
| `TextInputHost.exe` | 微软拼音 | 候选窗 UI 宿主（系统 UWP 组件） |

可见业界共识是：**DLL 只做必须留在应用进程里的事，其余全搬出去**。
`SGTool.exe` 正好是"一个 exe 里既有浮条又有设置入口"的现成先例。

## 不采用的做法

| 方案 | 为什么不 |
|:---|:---|
| 浮条由 DLL 画 | 每个宿主进程各画一份，同时开五个窗口就有五个浮条 |
| 浮条/设置做成 TSF 语言栏按钮 | 只能放图标，做不了浮条那种"点一下切中英"的交互；设置页更放不进去 |
| 状态放引擎内存 | 引擎没起来就不能判断中英；每次判定一次 IPC |
| 状态放 UI 进程内存 | UI 进程没启动 / 崩溃 → 状态丢失，还要设计降级，最后还是回到注册表 |
| 这次就把候选窗也搬到 UI 进程 | 见上，拿验证过的东西换没验证的 |

## 代价

- 多一个常驻进程（浮条窗口 + 托盘，几十 MB 以内）。
- 打包体积 +3MB 左右（Tauri + WebView2 依赖；WebView2 是 Win11 自带运行时）。
- 「改了配置什么时候生效」变成三类，界面里必须写清楚：
  DLL 侧（重启该应用）、引擎侧（重启 `rime-server`）、学习开关（立即）。

## 落地顺序

1. **全局状态**（本次）：注册表 + DLL 读值，中英全局、加中文标点开关。全部可单测。
2. **浮条**：`inklink-ui.exe` 的浮条窗口 + 托盘，读写注册表。
3. **设置台**：Tauri 窗口，先接已有配置（模糊音、标点、学习开关），再接词库管理。
4. **AI**：配置（端点/模型/密钥 DPAPI 加密）+ 续写/翻译/改写，异步、不进按键路径。
