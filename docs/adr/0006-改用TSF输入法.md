# ADR-0006：改用 TSF 输入法（薄壳 + 独立引擎）

- **状态**：已接受
- **日期**：2026-10-22
- **决策者**：用户
- **取代**：ADR-0001 的结论，以及 ADR-0005 的外挂方案（面板版降级保留）

## 背景

M0 用「热键唤起面板 + 键盘钩子」做到了能打字，但实机使用暴露四条结构性缺陷：

1. **光标位置只能猜**：`GetGUIThreadInfo` 对 WPS、Electron、UWP 类应用无效，后台条子位置会飘。
2. **按键要吞**：靠"是否拼写"判断该不该拦截，边界情况（大写、标点、数字、退格）反复出问题。
3. **不在输入法列表里**：`Win+Space` 里没有 inklink，用户必须先记热键，不像"正经输入法"。
4. **有拒绝心理**：一个常驻浮窗 + 自己的输入框，和用户对输入法的预期不符。

用户明确要求：「不像常规输入法会让用户有拒绝心理，不合我的规划」。

## 决策

改为实现 **TSF 文本服务**，但坚持两条约束：

1. **DLL 极薄**：只做 COM 胶水、按键转发、组合串显示、提交文本。
   **不含词库、不含引擎、不启动线程、`DllMain` 不做事。**
2. **引擎独立进程**：词库、切分、排序仍在现有 Rust 程序里，通过命名管道通信。
   DLL 崩了只影响当前应用；引擎崩了只影响输入法自己。

## 与上一版失败的根本区别

| | 上一版（rime.dll） | 本次 |
|:---|:---|:---|
| 引擎位置 | 编进 DLL，进每个进程 | 独立进程 |
| 线程 | DLL 里起后台线程 | 不起 |
| `DllCanUnloadNow` | 返回真实状态 → 卸载后代码还在跑 → 0xC0000409 | 恒 `S_FALSE` |
| 符号 | 无 | 有 |
| 调试 | 只能猜 | 引擎有单测与日志 |

## 已知代价（必须接受）

- **爆炸半径真实存在**：注册后 DLL 会被加载进 explorer、微信、浏览器等进程。
  实测一晚，8 个进程加载了它。这就是 TSF 的本质。
- **开发必须在隔离环境**：已建立 Hyper-V「Windows 11 开发环境」+ 快照 `tsf-base`，一切验证在 VM 内进行。
- **迭代慢**：`DllCanUnloadNow = S_FALSE` 导致 DLL 一旦加载就驻留，改代码要换路径或重启 VM。

## 后果

- `AGENTS.md` 铁律 1 改写：不再是"不写 DLL"，而是"引擎绝不进别人进程；DLL 只做薄壳"。
- 面板版保留为**免安装降级模式**（不注册 DLL 也能用）。
- 里程碑见 `docs/tsf-plan.md`：T1 注册可见 → T2 按键透传 → T3 出候选 → T4 组合串 → T5 兼容。
