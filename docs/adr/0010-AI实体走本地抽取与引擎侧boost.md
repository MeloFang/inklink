# ADR-0010：AI 实体走"本地抽取 + 引擎侧独立 boost"，不上云不建库

- 状态：已接受（切片 1 起实现，见 `PLAN.md`「M3」）
- 日期：2026-11-10
- 相关：[ADR-0002 AI 不进同步路径](0002-AI不进同步路径.md)、[ADR-0009 个人语料走引擎侧 boost 层](0009-个人语料走引擎侧boost层.md)

## 背景

M2 已经让"笔记里的词"进候选（`corpus.tsv` + 引擎 `apply_corpus()`）。M3 要更进一步：
输入法**知道你写的东西是什么**。验收场景是——

> 笔记里有「项目代号赤兔，负责人是张三」，打 `chitu` 不只出「赤兔」，
> 上屏后联想条能给出「张三 / 项目状态」。

这带出四个必须先定的问题：实体**怎么抽**、**存在哪**、**怎么用**、**隐私边界在哪**。

## 决定

### 1. 抽取：规则优先，本地模型可选

- **默认路径（规则）**：设置窗扫笔记，按结构抽实体——
  `## 词` 标题里出现的人名/项目名、`词：值` 形式的键值对、表格首列、
  `【】「」` 括起来的专名。零依赖、零网络、毫秒级。
- **增强路径（模型）**：设置里显式打开「用本地模型抽实体」，才去调
  `http://127.0.0.1:11434`（与 AI 面板同一个端点）。**默认关**，符合铁律三「默认不联网」。
- 两条路径产出同一种数据，模型失败就退回规则，不阻塞。

### 2. 存储：`entities.tsv` + `entity-next.tsv`，不进 SQLite

```
%LOCALAPPDATA%\inklink\entities.tsv      实体 \t 类型 \t 权重
%LOCALAPPDATA%\inklink\entity-next.tsv   实体 \t 后接词 \t 权重
```

理由：

- 引擎是 C++，读 TSV 是一行 `fgets`；引 SQLite 等于给引擎塞一个新依赖（违反 ADR-0001 的
  薄壳精神，也让装机包变大）
- 实体是**可整批重建**的派生数据，和 `corpus.tsv` 一样，不需要事务和随机写
- 排错简单：记事本能直接看

不放进 `corpus.tsv` 的理由：语料是"词"，实体带**类型和关系**，混在一起会让 `apply_corpus()`
承担两种语义；分开表，boost 层分开、权重分开，出问题好回滚。

### 3. 使用：先做候选 boost，再挂联想

- **切片 1**：`query()` 里在 `apply_corpus()` 之后再压一层 `apply_entities()`——
  实体命中的词排最前（权重高于普通语料，低于用户手动选择）。
  优先级链：**用户亲手选过 > 实体 > 语料 > 语言模型**。
- **切片 2**：联想条接 `entity-next.tsv`：上屏实体词后，按权重给它的属性/关联词
  （现在的联想条读 `phrase-pairs.tsv`，加一路数据源即可，窗口不动）。

### 4. 隐私：全部本地，默认关按钮

- 实体表、后接表都只落在 `%LOCALAPPDATA%\inklink\`，**永不上传**
- 设置窗提供「清空实体」；关掉导入就不再更新，已生成的文件可以一删了之
- 模型抽取只在用户显式打开时发生，且只打本机 `127.0.0.1`

## 后果

- 引擎加一小段 C++（两个 tsv 的加载 + 一层排序），`tools\build-engine.ps1` 重编一次
- 设置窗加一个「抽取实体」按钮 + 一个「用本地模型」复选框 + 结果计数回报
- 同步路径**不加延迟**：两张表在引擎启动时读进内存，查询时 O(1) 查表
- 抽取质量取决于笔记的**结构**（标题、键值对、表格）。笔记乱写就抽不出东西——
  这是可接受的：M3 的价值是"结构化的笔记有回报"，不是"任意文本都能理解"
- 实体数量设上限（2000 条），超了按权重截断，防止大 vault 把引擎内存撑爆

## 未采纳

- **SQLite**：引擎多一个依赖、装机包变大、查询优势在几千条量级用不上。
- **直接改 Rime 方案（custom_phrase / 词典合并）**：ADR-0009 已经踩过，排序不可控。
- **云端模型抽实体**：违反铁律三（默认不联网）与隐私主张，且离线不可用。
- **把实体塞进 `corpus.tsv`**：语义混淆，回滚粒度太粗。
