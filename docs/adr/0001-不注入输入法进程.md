# ADR-0001：不做进程内注入，采用独立面板 + 常驻引擎

- **状态**：已接受
- **日期**：2026-10-21
- **决策者**：用户 + Agent

## 背景

上一版 inklink 用 PIME/TSF，把 librime 编进 `PIMETextService.dll`，注入 explorer、WPS、记事本等**每一个**宿主进程。实机验证出现 `rime.dll` 内 `0xc0000409`（`__fastfail`），连带 WPS 崩溃、桌面黑屏；没有符号服务器、没有双机内核调试，每次复现要重启机器，最终放弃。

## 决策

1. **不做** TSF / DLL / 全局键盘钩子接管拼音输入。
2. 形态为**独立面板**：独立进程，热键唤起，所有业务逻辑在自己的进程里跑。
3. TSF 只允许在 **M4** 作为"薄适配层"出现——只转发按键与上屏结果，不含召回、排序、AI。

## 权衡

| 放弃 | 换来 |
|:---|:---|
| 原生无缝的输入体验（用户要多按一次热键） | 崩溃半径 = 自己，不再"一崩等于系统崩" |
| 一切依赖 IME 框架的能力 | 无需重启即可迭代；可单测、可日志、可断点 |

## 后果

- `PRODUCT.md` 里"面板形态"不能随意推翻；要改必须新开 ADR 并说明如何避免重蹈覆辙。
- 任何改动里出现"注入 / `SetWindowsHookEx` 键盘消息 / 写 DLL 到 `AppInit_DLLs`"必须先讨论并升级 ADR。
- M4 若真要做 TSF，必须先证明：有符号、能本地复现、崩溃不拖死宿主。
