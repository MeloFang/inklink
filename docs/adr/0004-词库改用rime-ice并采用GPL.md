# ADR-0004：改用 rime-ice 词表，项目采用 GPL-3.0

- **状态**：已接受（**取代 ADR-0003**）
- **日期**：2026-10-21
- **决策者**：用户
- **依据**：实测见 `docs/base-lexicon-eval.md` 第五节

## 背景

ADR-0003 选了 Rime `luna_pinyin`，理由是「唯一同时有词频与词级拼音」。下载真实文件后这个前提被推翻：

| 来源 | 实测 |
|:---|:---|
| `luna_pinyin.dict.yaml` | 7.1 万行里 4.9 万是**单字**；多字词仅 2.17 万且多为生僻（㓦劃、㔩葉）；只有 2,336 个**单字**带读音概率，**没有词频** |
| `essay.txt`（配套词频语料） | 44.3 万词，**繁体为主**（一個/這個/因爲）；与 luna 拼合后仅 9.4% 有整词拼音 |
| `rime-ice/base.dict.yaml` | 54.3 万词，简体，**100% 带音节切分**，权重 1–1926 万 |

拼合质量的反证：拿 essay 高频词碰 luna 注音，「我」被注成 `e`、「和」注成 `han`——同一字多读音时取首条必错。40 万词缺整词拼音，其中 19 万含多音字。

## 决策

1. 基础词库改用 **rime-ice** 的 `8105.dict.yaml`（通用规范汉字表）与 `base.dict.yaml`（按权重裁剪）。
2. **项目采用 GPL-3.0**，仓库根目录放 `LICENSE`。
3. 词库仍作为**独立资源包**产出（`data/base.tsv` + `manifest.json`），不提交进 git；产物是 rime-ice 的衍生作品，因此该数据文件本身按 GPL-3.0 分发。

## 权衡

- 放弃：MIT/Apache 的可能性。
- 换来：词库「开箱可用」——简体、带权重、音节完整，不用自己造词频表（自建估 1–2 周且质量更差）。
- 副作用：GPL-3.0 禁止闭源商用，与「开源、可被社区审计」的产品定位一致，不构成实际损失。

## 后果

- `PRODUCT.md`/`AGENTS.md` 的许可证描述统一为 GPL-3.0。
- 发布时必须在资源包里保留 rime-ice 的署名与 GPL-3.0 文本，并说明来源。
- 若将来改用其他词表，只需替换 `tools/build_base_lexicon.py` 的输入，引擎不受影响。
- 阈值（默认权重 ≥ 10000，约 7.7 万词）在转换脚本里可调，不为硬编码。
