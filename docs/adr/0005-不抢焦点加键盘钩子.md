# ADR-0005：面板改为「不抢焦点 + 键盘钩子」采集按键

- **状态**：已接受（**修订 ADR-0001 的边界**）
- **日期**：2026-10-21
- **决策者**：用户

## 背景

ADR-0001 为降低崩溃半径，规定「不做全局键盘钩子」。M0 阶段用「面板抢焦点 + 自己收 `keydown`」实现，
实机使用暴露三个无法绕开的问题：

1. 焦点在面板上，WPS / 浏览器的**光标消失**，用户不知道字会打到哪；
2. 面板拿着键盘，**数字键**只能当选词键，打不出数字；
3. 上屏后面板关闭，**打一个词就要重按一次热键**。

这三条是同一个根因：**外挂程序靠抢焦点才能拿到按键**。真输入法（TSF）在进程内，不存在这个问题。
而这个产品是离线的外挂输入面板，要么抢焦点，要么用系统级按键捕获。

## 决策

1. 面板窗口加 `WS_EX_NOACTIVATE`：唤出时**不夺取焦点**，目标应用保持前台，光标始终可见。
2. 面板可见期间，用 `WH_KEYBOARD_LL` 低级键盘钩子采集按键，命中我们处理的键就吞掉，否则放行。
3. 上屏时**不再切换焦点**（目标一直是前台），直接 `SendInput`。

## 硬约束（违反就等于回到了上一版的失败模式）

- **钩子回调里只做三件事**：读 `PANEL_VISIBLE`、判断按键、把字符塞进 channel。
  不做任何 IO、不做字符串处理、不调用 Tauri API。回调超过 ~1ms 就可能影响全系统输入。
- **必须忽略注入事件**（`LLKHF_INJECTED`）：否则我们自己上屏的 `SendInput` 会被钩子吞掉。
- **带 Ctrl / Alt / Win 的组合键一律放行**：否则热键 `Ctrl+\`` 会被自己吃掉。
- **面板不可见时钩子全程放行**：只做一次原子读就返回。
- 钩子安装失败要能降级：降级为「抢焦点」模式，宁可少个功能也不能让面板完全不可用。

## 风险与兜底

| 风险 | 影响 | 兜底 |
|:---|:---|:---|
| 回调阻塞 | 全系统输入卡顿；Windows 超时后会摘钩子 | 回调极简 + channel；实测回调耗时打印在调试日志里 |
| 钩子被安全软件拦截 | 按键收不到 | 安装失败时回退抢焦点模式，并在界面提示 |
| 吞键判断错误 | 某些键在目标应用里打不出来 | 只处理白名单键位（字母/数字/退格/回车/Esc/方向键/空格/撇号） |

## 后果

- ADR-0001 的「不注入」结论仍成立（仍然不写 DLL、不做 TSF、不进别人进程）；
  被修订的只是「连本进程内的系统级按键捕获也不用」这条过度保守的推断。
- 崩溃半径仍限于本进程：钩子在本进程，进程死了钩子随之消失。
- 上屏路径变短（不用切焦点），延迟更低，也顺手解决了「焦点闪回」。
